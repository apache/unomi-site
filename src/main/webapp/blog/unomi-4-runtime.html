Unomi 4.0 runtime

The Unomi 3 runtime, with 4.0.0 pins: Java 17, Karaf 4.4.12, Elasticsearch 9.4.3.

Unomi 3.0 is where this runtime landed: Java 11, Karaf Cellar, Hazelcast, and the Elasticsearch 7 High Level REST Client were retired there. Unomi 3.0.0 through 3.1.0 ship Java 17, Karaf 4.4.8, Elasticsearch 9.1.3, and persistence-based clustering. Unomi 4.0.0 keeps that model and updates the pins to Karaf 4.4.12 and Elasticsearch 9.4.3, and adds OpenSearch 3.7.0 as a second distribution.

Baseline upgrades

  • Java 17+ — required since Unomi 3.0; Java 11 installs cannot run 3.x or 4.0
  • Apache Karaf 4.4.12 — 4.0.0 pin (Unomi 3.0.0 through 3.1.0 used 4.4.8)
  • Elasticsearch 9.4.3 — Java API client, same as 3.x but moved from 9.1.3; OpenSearch 3.7.0 is the new peer distribution (see Elasticsearch 9 and OpenSearch)
  • Log / dependency pins — platform bump PRs keep Log4j and client stacks on supported lines

Persistence-based clustering (UNOMI-877)

Unomi 3.0 replaced Karaf Cellar and Hazelcast with this model. Nodes register ClusterNode documents in Elasticsearch or OpenSearch, publish heartbeats and stats, and discover peers through the shared index. The same mechanism underpins executor selection and locking for the cluster-aware task scheduler.

What operators should do

From Unomi 3.x the runtime is already in place: run the data migration (unomi:migrate 3.0.0), use Elasticsearch 9.4.3 (recommended; the supported range still starts at 9.0.3) or adopt OpenSearch 3.7.0, then add tenants and tasks. From Unomi 2.7, 4.0 also includes the Unomi 3 cutover: Java 17 hosts and Elasticsearch 7 (2.7.0 pins 7.4.2) to 9.4.3. The migrating from Unomi 3 post covers the REST and auth cutover; the manual holds the day-two runbooks.
