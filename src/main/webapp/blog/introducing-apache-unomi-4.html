Introducing Apache Unomi 4

A major Customer Data Platform release — runtime, multi-tenancy, and quality in Unomi 4.0.

Apache Unomi 4.0 is a major open-source CDP release. It brings the runtime operators need for production — Elasticsearch 9, Karaf 4.4, Java 17+, and persistence-based clustering — together with a platform-wide multi-tenancy refactor, OpenSearch, cluster-aware tasks, safer validation, and stronger tests.

A strong second theme: Unomi 4 is also built for AI agents that need real customer memory (retrieve, store, summarize, segment) over a stable open API. See Unomi 4 for AI agents.

The familiar REST map stays put: all 119 documented Unomi 2.x OpenAPI paths are still present in 4.0, with new endpoints added alongside. Optional V2 compatibility mode lets you phase authentication changes. Details in Migrating from Unomi 2.x.

The Unomi 4 journey

By the numbers (since ~2.7)

  • Tests outpaced implementation: test Java ~12k → ~63k while production Java grew ~70k (2.7) → ~118k (4.0), about 1.7×
  • Test/main Java ratio ~0.17 → ~0.53
  • About 1,148 unit @Test methods and 388 integration @Test methods on 4.0
  • API stability: 119 / 119 OpenAPI paths retained in 4.0; +12 additive paths
  • Unit tests, not only ITs: new in-memory PersistenceService harness for fast, independent service tests

Figures match Unomi 4 in numbers. Do not cite stale JaCoCo %. Current downloadable stable: v{{ site.data.unomi.latest.stable.version }}.

What’s in the box

  • Runtime: ES9 client, Karaf 4.4, persistence clustering, health checks (requires Java 17+)
  • Multi-tenancy: API keys and tenant isolation, plus OpenSearch, the task scheduler, condition validation, and request tracing
  • Upgrade bridge: V2 compatibility mode for phased 2.x client migration
  • Docs: migration and upgrade runbooks in the official manual
